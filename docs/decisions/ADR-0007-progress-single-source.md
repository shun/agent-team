# ADR-0007: 進捗管理の一本化(正は current-task.md、roadmap は計画+状態行のみ)

> 状態: 承認済み(2026-07-06 人間承認)/ 起案: Gen(玄)/ 2026-07-05(判断自体は同日の人間の案A採用)

- **背景**: Stage 1 当初、進捗が roadmap.md のチェックボックスと current-task.md の完了条件の2か所にあり、更新漏れ・食い違いが起きかけた
- **決定**: 進行中 Stage の進捗の正は `docs/work/current-task.md`(完了条件チェックリスト)。`docs/roadmap.md` は計画の正本として各 Stage の「状態」行のみを持ち、状態行の更新は Stage の節目に人間の承認をもって行う。進捗を二か所以上で管理しない
- **理由**: 同じ情報を二か所に持つと必ずずれる。「計画(変わりにくい)」と「進捗(毎セッション変わる)」は更新頻度が違うので、ファイルを分けて役割を固定する方が安全
- **捨てた選択肢**: (a) roadmap.md に進捗も持たせる — 正本の頻繁な更新が必要になり、人間承認フローと衝突する。(b) 進捗ファイルを Stage ごとに新設 — ファイルが増えすぎる。current-task.md はテーマ切り替え時に書き換える運用で足りる
- **影響**: roadmap.md 冒頭・workflow.md 4節に明文化済み
