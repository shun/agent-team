# ADR-0008: 設計判断が必要なことは ADR を残す(ルール自体の採用)

> 状態: 承認済み(2026-07-06 人間承認)/ 起案: Gen(玄)/ 2026-07-05(判断自体は同日の人間の追加ルール)

- **背景**: 土台づくりの中で「なぜこうしたのか」を後から問われうる判断が積み重なっていくが、チャットログは揮発的で、判断理由が残らない
- **決定**: 大小を問わず、後から「なぜこうしたのか」を問われうる設計判断は ADR として記録する。エージェントが作れるのはドラフト(候補)まで、正式な ADR への昇格は人間の承認が必要。ドラフトを残さずに設計判断を進めることは禁止する
- **理由**: 「なぜを残す」原則(workflow.md 7節)の具体化。責任を人格ではなく記録・成果物に持たせるというチーム原則の実装でもある
- **捨てた選択肢**: (a) 大きな判断だけ ADR 化 — 「大きい」の線引きが恣意的になり、結局残らない。(b) handoff-log への記録で代替 — セッション単位の記録に埋もれ、判断単位で参照できない
- **影響**: safety.md 3・4節(境界)/ workflow.md 6節(運用手順)に明文化済み。置き場と昇格方式は ADR-0001 で確定
