# ADR-0016: Tokiのテスト分析担当としての参加

> 状態: **承認済み（2026-07-19 人間承認）** / 起案: Gen（玄）

Tokiは、要件と設計をQA技法で品質リスク、カバレッジ、テスト条件、具体的項目、
期待結果、優先度、追跡関係へ変換する専門担当としてチームへ参加する。

- **決定**: Tokiを加入済みメンバーとし、`test-analysis.md`を主成果物とする。
- **決定**: 初期責務にテスト実行、証跡生成、実結果評価、最終合否、リスク受容を
  含めない。
- **決定**: 分析用期待結果は、人間の別承認がない限りanalysis-draft、承認者なし、
  ゲート利用不可とする。
- **決定**: 実装担当は実装レベル分析、TDD、自動化、回帰を所有し、Toki成果を
  非網羅の入力として使う。
- **決定**: 品質・セキュリティは共有責任とし、Toki成果を安全保証にしない。
- **決定**: テスト実行・実結果評価への将来拡張は、別試運転、Rinレビュー、人間判断、
  条件作成者と技術評価者の分離を必須とする。
- **試運転証跡**: 名前付きTokiは初回1回、再試行0回、fallbackなしで
  [test-analysis.md](../work/test-analysis.md)を作成した。成果物は379行、SHA-256は
  `3c0594e6a1d3eadf6c058161d4392848f37a8c36f1c04acf3eb5622306291c59`である。
- **条件付き採用**: 人間は`CD-01`を既知の不足として、成果物内容だけを1入力・
  1試行の条件付きで採用した。`CD-01`は各`TI-01`〜`TI-11`に一意な入力版が直接
  記載されていない契約差分であり、G4入力SHA-256
  `b2be3698f34b92d4056d4460413c0cafdc37fdcd824ceb623748322922bd82cf`との外部結合で
  追跡性を補うが、解消済みにはしない。
- **証拠境界**: 初回試運転はfresh context内部、read/write非逸脱、安全性、再現性、
  技術的強制を証明しない。後続転記では`analysis-draft`、承認者なし、ゲート利用不可、
  G4入力SHA-256を不可分に保持する。
- **理由**: TDDだけでは拾いにくい実装横断の境界、状態、組合せ、異常、回避経路を、
  実装前に人間がレビューできる形へ変えるため。
- **捨てた選択肢**: (a) 分析だけで具体項目を作らない、(b) 初回から実行・評価まで
  担う、(c) Tokiを置かずGenと実装担当へQA責務を分散する。
- **影響**: 5人構成が成立する。fresh性、read/write非逸脱、安全性、再現性、
  技術方式A・B・Cは未検証・未採用のまま維持する。
- **監査証跡**: 条件付き採用の詳細は
  [人間判断記録](../work/toki-stage4-initial-trial-human-decision-record.md)、評価とRinの
  反対意見は[Gen評価](../work/toki-stage4-initial-trial-gen-evaluation.md)、
  [初回レビュー](../work/risk-review-stage4-toki-initial-trial.md)、
  [差分再レビュー](../work/risk-review-stage4-toki-initial-trial-rereview.md)に残す。
