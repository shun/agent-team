# ADR-0010: Rin レビューの必須範囲は「正本変更ドラフトと final-proposal」

> 状態: 承認済み(2026-07-06 人間承認)/ 起案: Gen(玄)/ 2026-07-05(risk-review.md P1-2 の採用・判断C)

- **背景**: team.md は「Rin のレビューがない提案は不完全」と宣言するが、workflow.md の基本フローに Rin のステップがなく、更新契機は Stage 4 予定だった。必須範囲(全提案か、一部か)も未定義(Rin 指摘 P1-2)
- **決定**: Stage 4 を待たず workflow.md 基本フローに Rin レビューを組み込む。必須は**正本 docs の変更ドラフトと final-proposal の2種のみ**。それ以外は人間または Gen が必要と判断したとき
- **決定(指摘後のループ。2026-07-05 人間の指摘「指摘だけして終わる」を受けて追加)**: Rin の指摘には Gen が対応(修正または反論)し、修正分は Rin が差分を再レビュー(原則1周まで)。人間へは指摘を「修正済み / 見解相違(両論併記)/ 許容判断待ち」に仕分けて上げる。**Rin の OK は前提条件ではない**(拒否権なし。Gen-Rin 間で反対を解消し尽くさず、争点を見えるまま人間に出す — No Consensus Without Dissent の趣旨)
- **理由**: 全提案必須は安全だが遅く、都度指定は「軽いから不要」の骨抜きを招く。「後から変えにくいもの(正本)」と「人間の最終判断材料(final-proposal)」に限定すれば、コストを抑えつつ楽観合意の主経路を塞げる
- **捨てた選択肢**: 全成果物必須(速度低下が大きい)/ 都度指定のみ(No Consensus Without Dissent が運用として発動しない — P1-2 の失敗パターン)/ Stage 4 まで現状維持(宣言と手順の矛盾を2 Stage 放置)
- **影響**: workflow.md 1節(変更5)。範囲の線引きは実運用で見直してよい(成長ループ対象)
