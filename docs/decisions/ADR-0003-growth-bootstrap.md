# ADR-0003: 成長型ブートストラップ方式の採用(一括セットアップしない)

> 状態: 承認済み(2026-07-06 人間承認)/ 起案: Gen(玄)/ 2026-07-05(判断自体はロードマップ策定時の人間の方針)

- **背景**: エージェントチームの導入方法として、最初から5人分の定義と全ファイルを置く「一括セットアップ」と、必要になったときに一人ずつ迎える「成長型」がありうる
- **決定**: 最初の一人(Gen)を最小構成で生み、実タスクで必要になったファイル・メンバーから順に足す。すべての変更は成長ループ(提案 → 試す → 振り返り → 人間承認 → 反映)を通す
- **理由**: 使われない定義・ファイルは腐る。実際の必要性に駆動されて足したものだけが検証済みの土台になる。「名前だけ増えて出力が同じ」という失敗条件(memo セクション25)の早期検出にもなる
- **捨てた選択肢**: 一括セットアップ(memo の14ファイル構成をそのまま展開)— 検証されていないルールが大量に正本化され、形骸化のリスクが高い
- **影響**: docs/roadmap.md 全体の構成原理。育成の原則「一度に迎えるのは一人まで」「ファイルは必要になってから作る」として明文化済み
