# ADR-0015: Kaiの条件付き参加と技術的強制の再判断ゲート

> 状態: **承認済み（2026-07-19 人間承認）** / 起案: Gen（玄）
> 元候補: [Kaiの条件付き参加と技術的強制の再判断ゲート](../work/adr-drafts/2026-07-19-kai-conditional-participation.md)

名前付きKaiのfresh session試運転では、指定形式の設計比較成果物を1ターンで
出力した。要件IDは形式適合のみで、意味上の照合と品質比較は実施していない。
これは名前付き起動と初回の形式契約充足の1サンプルであり、Kai固有の価値・
再現性、read/write非逸脱、技術的強制の証明ではない。

- **決定**: Kaiをチームへ参加させ、既存の安全境界とタスク単位契約に従う
  設計成果物の作成を担当させる。
- **決定**: sandbox、permission profile、専用実行空間、allowlistゲートウェイ、
  事後監査の採否と、実現可能性確認・PoC・実装を保留する。
- **決定**: コード実装、PoC、設定変更、外部連携、高権限・本番操作、読ませては
  いけない機密・blind入力、または既存安全境界やタスク単位契約を越える
  read/writeを含む依頼は、Kaiへ割り当てる前に技術的強制の要否を人間へ戻す。
- **決定**: Tokiの加入は本判断に含めず、別の明示承認まで開始しない。
- **理由**: 設計比較を担当する役割は利用可能になった一方、初回成功を権限制御の
  成功へ拡張せず、必要性が具体化した時点で技術方式を選べる状態を保つため。
- **捨てた選択肢**: (a) 技術的強制の方式が決まるまでKaiを参加させない、
  (b) 初回試運転だけで設計案A・B・Cのいずれかを採用する、
  (c) 名前付き起動成功をread/write境界の技術的強制が成立した証拠として扱う。
- **影響**: Stage 4は進行を続ける。Kaiは参加済み、Tokiは未着手とし、
  技術方式は保留する。再判断条件に該当する依頼を通常運用へ流さない。
