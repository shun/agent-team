# ADR-0014: ツール別エージェントアダプタの展開順序と比較ゲート

> 状態: 承認済み(2026-07-18 人間承認) / 起案: Gen(玄)
> **比較順は更新しない。** 2026-07-22 の人間依頼により、比較ゲート完了前に
> Antigravity adapter を追加した。例外記録は
> [ADR-0025](ADR-0025-antigravity-subagent-adapter.md)。Claude Code 比較は
> 未実施のまま残す。本 ADR が捨てた「実測なしの順序固定」は、今も捨てたまま。

- **背景**: Stage 2 では Claude Code 用 Rin アダプタの実起動を確認できず、アダプタ経路が Stage 3 の前提として持ち越された。一方、現在の主実行環境は Codex であり、作業コピーには Codex 用 `.codex/agents/rin.toml` が追加されている。元ロードマップの「他ツール対応は Stage 6 以降」と実態を再整合する必要がある。
- **決定**: 最初に Codex で「Gen が名前付きサブエージェントへ委譲し、Markdown 成果物を受け取り、Gen が統合する」基準フローを確立する。
- **決定**: Stage 3 開始前に、版を固定した fresh session で Rin の機能スモーク2回目を成功させる。新規ロール自身の名前付き起動確認も完了条件から外さない。
- **決定**: Stage 3 の要件整理までは instruction-based な安全境界の残留リスクを条件付きで許容する。要件整理後、コード作業・外部連携・高権限操作へ進む前に技術的強制の要否を再判断する。
- **決定**: 次の比較環境は Claude Code、その後は Antigravity とする。ただし順位の根拠は固定的な好みではなく、Codex と同一スモークテストによる起動可能性・正本参照・権限制御・成果物受け渡し・人間の観測可能性とする。
- **決定**: ツール別アダプタは薄く保ち、役割・安全境界・ワークフローの正本は `docs/agent/` に置く。
- **理由**: Codex は現在の主実行環境で最短で成功経路を作れる。Claude Code は既存アダプタがあり比較コストが低い。Antigravity はマルチエージェント・成果物中心の適合可能性があるが、同一テスト前にClaudeとの順序を逆転する根拠は不足している。
- **捨てた選択肢**: (a) Claude Code / Antigravity の順序を実測なしで固定する。(b) 3環境を同時対応する。(c) Codex 対応を Stage 6 まで保留する。(d) 1回の自己申告ベースの成功だけで Stage 3 前提を確定する。
- **影響**: `.codex/` を正本保護対象へ追加し、Gen の委譲責任・再試行上限・未信頼レビュー対象の扱いを正本化する。Codex の1回目スモークは成功済みだが、current-task は fresh session の2回目成功まで進行中とする。

## 判断証跡と再判断条件

- 採用順はCodex、Claude Code、Antigravityとし、各環境を同一スモークの
  名前付き起動、正本参照、権限制御、成果物受け渡し、人間の観測可能性で比較する。
- Codexの初回スモークだけではfresh性、instruction外のread/write非逸脱、技術的強制を
  証明しない。Stage 3前の2回目成功を当時の進行ゲートとし、コード、外部連携、
  高権限操作へ広げる前の技術的強制判断を別ゲートとして残した。
- 比較対象の実行環境、公開される権限制御、または名前付き起動経路が変わった場合、
  同じ評価軸で順序を再判断する。過去の順位を恒久的な製品評価として使わない。
- 昇格元ドラフトは本ADRへ判断内容を吸収済みであり、決定の解釈に必要な外部依存はない。
