# ADR-0019: コード実装はテスト分析と項目承認を先行する

> 状態: **承認済み（2026-07-19 人間承認）** / 起案: 人間 / 整理: Gen（玄）

Toki加入により、保留していたテスト分析先行の実装フローを適用できる状態になった。

- **決定**: コード実装前にTokiがQA技法を使ったテスト分析を作る。
- **決定**: 人間がテスト分析とテスト項目を承認するまで、実装コードを書かない。
- **決定**: 承認後、実装担当がWhyを添えたテスト骨組みを作り、人間レビューを受ける。
- **決定**: 骨組みレビュー後、実装担当がRED → GREEN → REFACTORで実装する。
- **決定**: 要件・設計変更、新しい品質リスク、実行不能が判明した場合、必要範囲を
  Tokiの再分析と人間承認へ戻す。
- **決定**: Tokiは初期責務でテスト実行・実結果評価を担わず、実装担当のTDD、
  自動化、回帰責任を置き換えない。
- **理由**: 実装前に横断的な漏れを分析し、各テスト項目の必要性を人間が確認したうえで
  最小実装へ進むため。
- **捨てた選択肢**: (a) 実装開始後にテスト項目を決める、(b) Tokiが実行・評価まで
  一貫して担う。
- **影響**: `workflow.md`へ実装テーマの必須ゲートを追加し、保留していた運用ルールを
  正本へ統合する。
