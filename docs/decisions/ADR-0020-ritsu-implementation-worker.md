# ADR-0020: Ritsuを実装・複合実行担当として一人ずつ迎える

> 状態: **承認済み（2026-07-20 人間承認）** / 起案: 人間 / 整理: Gen（玄）

現行5人は専門判断と成果物制作を同じ担当内で行うため、判断確定後の作業も直列化する。
人間はToki関連のコミット後、Hayateを同時に進めず、Ritsuを次の一人として進める判断をした。

- **決定**: Ritsuを実装・複合実行担当の`加入準備中`メンバーとして正本へ追加する。
- **決定**: 必須実行条件を`gpt-5.6-luna` / reasoning effort `high`とし、信頼できる
  platform証跡を確認できなければfallbackせず`blocked`とする。
- **決定**: 専門担当は判断中核と受入れ確認を保持し、初期の物理dispatch、競合調整、
  証跡統合をGenへ集中する。
- **決定**: 加入状態を`未加入 → docs-only試用 → コード試用 → 役割別加入`に分ける。
- **決定**: docs-only試用は、試行専用の新規`docs/work/`出力だけに限定する。
- **決定**: コード試用は、技術的write隔離、基準版、競合停止、独立差分確認、復旧主体を
  実装・実証し、人間が別途承認するまで開始しない。
- **決定**: Ritsuの試運転、振り返り、人間判断が終わるまでHayateを進めない。
- **理由**: 専門判断の品質と現行安全境界を維持しながら、判断後の制作・実装・検証を
  低遅延workerへ分離し、end-to-endの速度改善を検証するため。
- **捨てた選択肢**: (a) RitsuとHayateを同時加入させる、(b) 専門担当から直接spawnする、
  (c) docs-only成功をコード能力へ外挿する、(d) Luna利用不能時に別modelへfallbackする。
- **影響**: `team.md`、`workflow.md`、`roadmap.md`、Codex adapterを更新する。Stage 5は
  未着手のまま維持し、Ritsuのgrowth loop完了後に開始ゲートへ戻る。
