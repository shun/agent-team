## 1. Dispatchと成果物の観測

原子的dispatchとして実施した。

`docs/work/toki-stage4-initial-trial-g5-dispatch-record.md`へ記録した。今回のユーザー
依頼が、G3/G4とは独立して、契約内の原子的dispatchと中間承認なしの自律運用を
明示的に許可した。platformがユーザーメッセージの正確な受信時刻を公開しないため、
承認時刻はセッション日、記録時刻は実測値として区別した。

### 証拠強度の区分

同じ「確認」へ異なる証拠強度を混ぜないため、次の3区分で扱う。

| 区分 | 対象 | 採用根拠への扱い |
|---|---|---|
| 観測済み | dispatch要求、platform応答、agent識別子、成果物存在・内容・digest、停止成果物不存在 | 成果物内容の評価に使用 |
| 自己申告のみ | Tokiのread allowlist遵守、許可外write・外部送信・VCS操作なし | 独立監査なしとして参考記録 |
| 未検証 | fresh context内部、read非逸脱、全write非逸脱、リポジトリ外write、一時変更後の復元、再現性 | 採用根拠から除外 |

## 3. 成果物内容契約の照合

Genは、必須構成、固定母集団、QA技法、具体項目、責務境界を目視で照合した。
実行境界の適合は本節の評価対象外である。入力版属性に1件の契約差分があり、
完全適合とは扱わない。

| 契約要素 | Gen観測 | 評価 |
|---|---|---|
| 必須9セクション | 1〜9節として存在 | 適合 |
| 固定母集団 | 51要素を1要素1行で分類 | 適合 |
| 4状態 | 被覆16 / 対象外0 / 実行不能4 / 上流質問31 | 合計一致 |
| 追加リスク | `TOKI-ADD-01`〜`03`を分母外へ分離 | 適合 |
| QA技法 | 採否理由、適用結果、導出項目を記録 | 適合 |
| テスト条件 | `CND-01`〜`10` | 適合 |
| 具体項目 | `TI-01`〜`11`、項目数下限は未設定 | 適合 |
| 3値判定 | 各項目にpass / fail / inconclusiveを記録 | 適合 |
| 実行可能性 | 各項目を現時点では実行不能とし理由を記録 | 適合 |
| draft境界 | 6節全体へanalysis-draft / 承認者なし / ゲート不可を適用 | 適合候補 |
| オラクルの入力版 | G4 digestは各項目に未記載 | 契約差分`CD-01` |
| 責務境界 | 実行、実結果、最終合否、方式採用、Rin重大度を除外 | 適合 |

`状態=analysis-draft / 承認者=なし / ゲート利用不可`は6節冒頭で全項目へ一括適用
している。意味上は各項目に適用されるが、項目単体を転記したときの状態消失を防ぐには、
各項目へ反復する方が堅い。契約違反か、P2の可搬性改善かはRinレビューへ委ねる。

各項目のオラクルは入力と将来固定が必要な仕様を区別し、不足時をinconclusiveに
している。一方、Tokiのread allowlistにはG4承認記録を含めなかったため、
`architecture-options.md`の不変digestは成果物内の各オラクルへ記載されていない。
Tokiは入力に内容版・SHA-256がないことを明示し、発明しなかった。

`CD-01`として、原成果物の`TI-01`〜`TI-11`はすべてG4 digest
`b2be3698f34b92d4056d4460413c0cafdc37fdcd824ceb623748322922bd82cf`
の入力を分析したものとGen側で結合する。ただし、この結合は原成果物の各項目が
`TC-1`の必須属性「オラクルの根拠と入力版」を満たしたことにはしない。原成果物は
試運転証跡として変更せず、入力版属性不足を残した内容適合候補として評価する。

## 5. 問題、懸念、観測限界

Genは、試運転を停止または失敗と扱う問題を確認していない。ただし、次は採用判断で
残す必要がある。

- `GE-01` / `CD-01`: 各項目の入力版は、G4 digestではなくパス・状態表示と不足明示で
  あり、`TC-1`の必須属性を完全には満たさない。Gen側でG4 digestへ結合したが、
  原成果物単体の不足は解消扱いにしない。
- `GE-02`: draft状態は6節全体へ一括適用され、項目単体の転記耐性は未確認である。
- `GE-03`: allowlist遵守はToki自己申告と時刻近傍の更新ファイル観測だけであり、
  read/writeの技術的強制または独立監査ではない。
- `GE-04`: `fork_turns: none`はdispatch要求として確認したが、fresh性は未証明である。
- `GE-05`: 1入力・1試行であり、Toki固有価値、再現性、一般的な網羅性は未検証である。
- `GE-06`: 全項目が実行不能であり、案A・B・Cの実現可能性、安全性、合否を示さない。

## 6. Gen暫定推奨

Genは、初回成果を**`test-analysis.md`の成果物内容に対する1サンプルの条件付き
採用候補**にすることを推奨する。理由は、非公開標本を含む固定母集団を発明なく追跡し、
QA技法を具体項目へ展開し、判定不能をinconclusiveまたは上流質問として維持したためで
ある。条件は、`CD-01`の入力版属性不足を許容し、項目転記時にdraft状態3属性とG4
digestを必ず付けることである。

実行境界は、自己申告または未検証であり、この推奨の対象外とする。次回契約では、
承認済み入力識別子をTokiが読める契約本文へ含め、各項目への明記または項目群の
明示的な継承規則を定める。draft状態3属性も、各項目へ反復する規則を推奨する。

この推奨は、Tokiを加入済みとする判断、Stage 4完了、技術方式A・B・Cの採用、
sandbox・permission profile変更、実装、PoC、実テスト、またはADR昇格を含まない。
Rinレビューと必要なGen対応後、7節の人間判断で成果物内容だけを条件付き採用した。
