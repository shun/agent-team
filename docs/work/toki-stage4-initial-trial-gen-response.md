## 2. P1-1への対応

`docs/work/toki-stage4-initial-trial-g5-dispatch-record.md`を新規作成した。承認者、
セッション日、記録時刻、dispatch引数、停止条件、Fast Laneの中間承認省略、
G6+G7原子的dispatchの残留リスク、実値と結果を記録した。

正確なユーザーメッセージ受信時刻はplatformから取得できないため、発明せず、
承認日と記録時刻を分けた。この証拠で、G3/G4の未承認記録より後に、今回の人間依頼が
G5を独立承認したことを追跡する。

## 3. P1-2への対応

Gen評価の対象を`test-analysis.md`の成果物内容へ限定した。「契約適合証跡」という
広い表現を削除し、次の区分を追加した。

- 観測済み: dispatch要求、platform応答、識別子、成果物、digest、停止成果物不存在。
- 自己申告のみ: Tokiのread allowlist遵守と許可外操作なし。
- 未検証: fresh性、read非逸脱、全write非逸脱、外部境界、一時変更、再現性。

自己申告と未検証の実行境界は、成果物内容の条件付き採用根拠から除外した。

## 4. P1-3への対応

原成果物の全`TI-01`〜`TI-11`を、G4 digest
`b2be3698f34b92d4056d4460413c0cafdc37fdcd824ceb623748322922bd82cf`
の入力を分析したものとGen評価で明示的に結合した。

ただし、これは原成果物内の各項目が必須属性を満たしたことにはしない。`CD-01`として
契約差分を残し、人間には、この不足を許容して成果物内容だけを条件付き採用するか、
必須契約違反として保留するかを戻す。次回は承認済み入力識別子をTokiが読める契約へ
含め、各項目または明示的継承欄へ固定する。

## 5. P2-1への対応

初回成果物内では、6節冒頭の3属性が全項目へ適用される解釈を維持する。ただし、項目を
別成果物、Issue、テスト管理票へ転記する場合は、次を必須とする案を人間へ戻す。

- `状態=analysis-draft`
- `承認者=なし`
- `ゲート利用不可`
- G4入力digest

次回契約では、一括継承を使わず、各項目へ3属性と入力版を明記するルールを推奨する。

## 6. 差分再レビュー依頼範囲

差分再レビューでは、P1-1〜P1-3とP2-1の対応箇所だけを確認する。EP-1標本の再評価、
原`test-analysis.md`の再評価、指摘の再掲、または新しい責務への拡張は行わない。

Genの推奨は、`CD-01`とP2-1の転記条件を人間が許容する場合に限り、成果物内容を
1入力・1試行の条件付き採用候補とすることである。加入済み、Stage 4完了、技術方式、
安全性、実行境界の適合へ接続しない。

Rin差分再レビューは、対応差分に新しいP0/P1なしと判定した。P1-2は解消、P1-1と
P1-3は技術ドラフト修正済み・人間判断待ち、P2-1も技術ドラフト修正済み・人間判断
待ちである。原則1周を完了したため、同じ対象への再々レビューは行わない。

差分再レビューで指摘されたP2の表現リスクに対応し、Gen評価2節のA2説明へ`CD-01`を
併記した。この事後表現修正は、原成果物または判断内容を変更しない。
