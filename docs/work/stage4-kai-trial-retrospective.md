# Stage 4 Kai名前付き試運転 振り返り

- 状態: **人間判断済み（Kai参加を条件付き採用）**
- 作成者: Gen（玄）
- 対象: 名前付きKaiの起動と `architecture-options.md` 初回成果

## 1. 結論候補

Genの暫定評価は、**名前付きKaiが初回契約を満たす比較成果物を生成可能だったという1サンプルを、条件付き機能証跡として採用候補にする**である。

今回だけでは、Kai固有責務によるGen / default agentとの差分、再現性、継続的な増分価値は分からない。人間が1サンプルを加入判断に十分とみなすか、不十分でも限定運用を許容する場合だけ、Kai加入ループを条件付き完了候補とする。

条件は、今回の成功を「名前付き起動と概念設計成果物の初回機能証跡」に限定し、read非逸脱、repo全体write非逸脱、各案の実現可能性、技術的強制を未検証のまま維持すること。技術方式の採用・実現可能性検証・実装は別の人間判断ゲートとする。

## 4. 初回サンプルから確認できたこと・できないこと

- 要件IDと未確認事項を参照し、責任境界の異なる3案を提示した。参照元との意味上のトレーサビリティは未照合である。
- instruction遵守を技術的強制として扱わず、防止・検知・事後検証を分離できた。
- 単一案を既定路線にせず、成立しない条件と残留限界を比較材料として残せた。
- Genが設計案を再発見せず、契約適合と証跡限界の確認へ役割を分けられた。ただし、Gen単独時との品質・工数比較は実施していない。

一方、3案とも概念設計であり、現在のCodexに必要な機能が存在するかは分からない。今回の出力品質だけを根拠に、案A/B/Cのいずれかを実装可能・安全・推奨と扱ってはならない。Kai固有価値、汎用agentとの差、再現性も未検証である。

## 6. 人間へ提示した判断事項

試運転レビュー後、人間へ次の事項を提示した。判断結果は8節に記録する。

1. 名前付きKaiの起動と初回成果を、概念設計・未検証かつ1サンプルという条件付き機能証跡として採用するか。
2. Kai固有増分・再現性は未検証でも、1サンプルを加入判断に十分とみなし、役割定義とadapterを現状維持してKai加入ループを条件付き完了とするか。追加試運転を求めるか。
3. 技術的強制が成立するまで、Kai利用を、人間が機密・個人・顧客・本番データ・秘密情報を含まないと確認したリポジトリ内Markdown、固定read allowlist、`docs/work/`新規1成果物、既存時停止、外部送信・VCS・実装・設定変更なしへ制限するか。
4. read/write非逸脱・実現可能性・技術的強制を未検証として残し、方式採用・検証・実装を別ゲートにするか。
5. Toki開始は、Kai加入ループの扱い確定に加えて人間の明示承認を必須とするか。保留・却下・条件未充足では停止を継続するか。
6. 要件IDの形式適合だけを今回の初回契約充足に十分とし、意味上の照合は別途必要になったときに行うか。

承認に含まれないものは、案A/B/Cの採用、コード・PoC・設定変更、外部調査・連携、高権限操作、正本変更、Stage 4全体の完了、Toki加入である。

## 8. 人間判断

人間は、初回1サンプルの限界を残したまま、Kaiをチームへ参加させる判断をした。
Kai加入ループは条件付き完了とし、役割定義とadapterは変更しない。

技術的強制、案A・B・Cの採否、実現可能性確認、実装は保留する。当面は既存の
安全境界とタスク単位契約に従う設計成果物だけをKaiへ依頼する。コード、外部連携、
高権限操作、または読ませてはいけない機密・blind入力を含む案件は、割当前に
人間へ再判断を戻す。Toki開始は今回の判断に含めない。
