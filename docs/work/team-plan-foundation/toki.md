## 対象範囲とテストベース

本分析は、指定されたチーム計画・実行フローの準備状態、計画表現、依存遷移、
再実行、Bash 入口を対象にする。現行の Mission Room、既存成果物、既存の
未コミット変更、実装の方式選定は対象外である。

- テストベース: `docs/work/team-plan-foundation/request.md` の「人間が指定した
  挙動」「固定する前提と安全境界」「レビュー論点」。
- 分析上の対象母集団: 人間が指定した挙動 8 項目とレビュー論点 6 項目。
  この母集団は本レビューの追跡用であり、承認済み受け入れ母集団ではない。
- レビュー論点 6 は、READY-01 から BASH-02 を将来の実装後に確認するための
  条件群として追跡する。ただし本レビューでは実装後の確認を実施しない。
- 現在の制約: このレビューでは `tmp/` を変更しない。したがって
  `tmp/PLAN.md` の作成・実行確認は本分析の実施対象外である。
- 非対象: 実行担当の TDD、自動化、回帰、ランナー実装、Bash コマンドの実行、
  外部送信、VCS 操作。

## 品質リスクとカバレッジ方針

以下の優先度は、テスト設計と将来の実行順の候補であり、Rin の重大度や人間の
リスク受容を表すものではない。項目数ではなく、計画の誤遷移を防げるかで
カバレッジを判断する。

| リスク ID | 品質リスク | テスト優先度 | 主なカバレッジ |
| --- | --- | --- | --- |
| QR-01 | 未解消の不明点や役割成果物の欠落を残したまま計画を実行可能と扱う。 | T1 | 準備判定、停止、人間への差戻し |
| QR-02 | タスク、依存、Wave、完了条件の表現が曖昧で、順序が判断できない。 | T1 | `PLAN.md` の構造、依存グラフ、並行 Wave |
| QR-03 | 依存元の完了確認・チェック前に、依存先の Bash 起動を許す。 | T1 | 状態遷移、負のシナリオ、起動ガード |
| QR-04 | 根拠のない再実行または進展のない反復が続く。 | T1 | 再試行の根拠、停滞判定、人間への相談 |
| QR-05 | `codex exec` または `agy -p` が依存ガードを迂回して起動する。 | T1 | Bash 入口、起動前検査、未起動の観測 |
| QR-06 | 「小さいタスク」「完了確認」「進展なし」や安全な引数化の意味が未定義で、判定不能になる。 | T2 | 上流質問、Blocked 表示、観測可能性 |

## 選ぶ QA 技法

計画フローは、入力内容より状態と依存関係の誤りが主な失敗面になる。そのため、
次の技法を組み合わせる。いずれも名称だけで品質を主張するものではない。

- 状態遷移テスト: 計画準備、完了確認、チェック、依存先起動、再試行、停滞の
  許可・停止遷移を検査する。
- 依存グラフとトポロジカル順序の検査: 依存関係が存在するタスクを順序どおりに
  表せることと、循環・欠落・自己依存を検出する。
- シナリオテスト: 全役割が Markdown 成果物を返す正常系、未解消の不明点、
  独立タスクの並行 Wave、依存未完了の起動要求を扱う。
- ネガティブテスト: 完了未確認、未チェック、根拠のない再試行、進展なしの反復、
  ガードを通らない Bash 起動を拒否できるか確認する。
- リスクベースドテスト: QR-01 から QR-05 を T1 とし、計画が誤って先へ進む
  経路を先に検査する。

## 分析ドラフトのテスト条件

各条件の期待結果は、テストベースから導いた分析用ドラフトである。実装後に
受け入れ判定へ使うには、人間が承認した設計版、観測方法、オラクルを各条件へ
紐付ける必要がある。

表中の **Blocked** は、必要な入力・承認・観測が欠けて次の遷移を止める状態を
表す。このとき当該条件の判定値は **inconclusive** とし、Pass または Fail と
扱わない。

| ID | 前提・入力または操作 | 観測対象 | 分析用の期待結果、判定、実行可能性 | 根拠・追跡 |
| --- | --- | --- | --- | --- |
| READY-01 | 「〜を計画して」の依頼に対し、7 役割の結果がそれぞれ Markdown 成果物として識別でき、未解消事項がない。 | 役割ごとの成果物、受渡し参照、準備状態。 | **Pass:** 全役割の結果を混ぜずに追跡でき、実行可能な計画の作成へ遷移できる。**Fail:** 役割の欠落または未解消事項を隠して遷移する。**Blocked:** 役割参加または未解消事項の状態を観測する方法がない。将来は成果物の静的確認で実行可能。 | 人間指定挙動 1・2、レビュー論点 1・2、QR-01 |
| READY-02 | 計画に影響する不明点が 1 件残る状態で、計画作成を要求する。 | 不明点の内容、影響、質問先、準備状態、`PLAN.md` 作成要求の処理。 | **Pass:** 計画を実行可能として扱わず、人間への最小質問を残して停止する。**Fail:** 仮定で埋める、または人間確認前に進める。**Blocked:** 不明点が計画に影響するかを記録できない。将来は停止経路のシナリオで実行可能。 | 人間指定挙動 2、安全境界、レビュー論点 2、QR-01 |

| PLAN-02 | 依存グラフ `A → C`、`B → C` を持つ計画を与える。循環、自己依存、存在しない依存先も負の入力として与える。 | 計画上の順序、依存の有無、Wave、拒否または Blocked 理由。 | **Pass:** A と B は C より前に置かれ、循環・自己依存・存在しない参照は実行可能計画として扱われない。**Fail:** 依存先を先行させる、または不正な依存を見逃す。**Blocked:** 依存を機械または人間が一意に解釈できない。循環検査は「依存順に並べる」ための整合性検査である。 | 人間指定挙動 7、レビュー論点 3・4、QR-02 |

| RETRY-02 | 前回から新しい観測事実・仮説・変更がない未完了タスクで、再実行を繰り返し要求する。 | 反復間の差分、進展判定、停止表示、人間への相談内容。 | **Pass:** 進展のない反復を止め、観測事実・影響・最小質問とともに人間へ相談する。**Fail:** 停止条件なしに再実行し続ける。**Blocked:** 「進展なし」の比較基準または再試行上限がない。数値上限はテストベースにないため、本分析では補完しない。 | 人間指定挙動 6、レビュー論点 5、QR-04・QR-06 |

## 失敗・Blocked の扱い

失敗は、将来人間が承認した設計とオラクルに対して、上表の期待結果に反する
観測事実が得られた状態を指す。Blocked は、要求を仮定で補わず、判定または次の
遷移を止めて上流へ戻す状態である。どちらも最終合否やリスク受容ではない。

| 区分 | 事実として扱う条件 | 必要な処理 |
| --- | --- | --- |
| Failure | 未解消事項または役割成果物の欠落を残して、実行可能な計画または `PLAN.md` を作る。 | 準備判定を不合格にし、未解消事項を人間へ戻す。 |
| Failure | タスクのチェックボックス、ゴール、完了条件、依存参照のいずれかが欠け、依存順を判定できない。 | 計画を実行可能として扱わず、計画表現を差し戻す。 |
| Failure | 依存元の完了確認・チェックより先に依存先を起動する、または Bash 入口がそのガードを迂回する。 | 依存先を起動せず、違反した遷移と影響を記録して上流へ戻す。 |
| Failure | 前回結果に根拠を持たない再試行、または進展なしの反復を継続する。 | 再試行を止め、人間への相談に必要な観測事実と最小質問を残す。 |
| Blocked | 不明点への人間回答、役割成果物、または `tmp/PLAN.md` を許可する承認済み境界がない。 | 計画作成・実行を進めず、欠ける判断または承認を質問として返す。 |
| Blocked | 完了確認のオラクル、チェックの記録、依存検査と Bash 呼出しの順序を観測できない。 | 合格とも不合格とも言わず、観測点と責任者の設計を上流へ求める。 |
| Blocked | 「小さい」「独立」「進展なし」、再試行上限、Bash の安全な引数化またはランナー失敗時の意味が未定義である。 | 未定義部分を補完せず、対象タスクまたは該当受け入れ条件を停止する。 |
