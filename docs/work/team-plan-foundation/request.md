# チーム計画オーケストレーション設計レビュー

> 状態: レビュー中（2026-08-16 の人間依頼）

この成果物は、Mission Room の前に導入する「人間が『〜を計画して』と
依頼したときのチーム計画・実行フロー」を検討するための共通契約である。
レビュー担当は、このファイルを入力として指定された成果物だけを作成する。

## 目的

7人のエージェントチームが、実装や調査を始める前に不明点を解消し、依存順と
並行可能性が明示された実行可能な計画を作る仕組みを設計する。人間の判断が
必要な事項を仮定で埋めず、堂々巡りも止められることを完了条件とする。

## 人間が指定した挙動

- 人間が「〜を計画して」と依頼したら、全員が Markdown 成果物を介して議論する。
- 議論の結果に不明点が残れば、人間へ確認してから進める。
- 作業は小さく分割し、独立したものは並行できるように計画する。
- 実行可能になった時点で `tmp/PLAN.md` にチェックボックス付きのタスクリストを作る。
- 各タスクには、ゴールと完了条件を必ず記載する。
- 未完了のタスクは根拠ある次の仮説で再実行する。進展のない反復は止め、人間へ相談する。
- タスクは依存順に並べ、完了を確認してチェックしてから依存先へ進む。
- 実行は Bash を入口とし、`codex exec "…"` または `agy -p "…"` を基本とする。

## 固定する前提と安全境界

- 人間が最終判断者であり、未確認事項・リスク受容・設計採否をエージェントだけで決めない。
- チーム内の受け渡しは直接会話ではなく、役割ごとの Markdown 成果物で行う。
- 現行の Mission Room 実装、既存成果物、既存の未コミット変更はこのレビューの対象外である。
- このレビュー中は `tmp/` を変更しない。`tmp/PLAN.md` の狭い例外は、採用する設計に
  必要なら後続の正本変更として明示する。
- レビュー担当は、指定された自分の成果物以外を変更せず、VCS・ネットワーク・実装を行わない。

## レビュー論点

1. 「全員で議論」を、役割責務を混ぜずに実現する成果物・ラウンド設計。
2. 不明点を分類し、いつ人間へ戻すかの停止条件。
3. 依存順・並行 Wave・タスクの完了条件を矛盾なく表現する `PLAN.md` 形式。
4. Bash から Codex / Antigravity を安全に起動し、依存未完了や未チェック遷移を防ぐ方法。
5. タスク再実行と堂々巡り判定の、観測可能かつ無駄の少ない基準。
6. 実装後にこの仕組みが守られていることを確認する受入れ条件。

### Toki 固有の起動契約

Toki のレビューは、fresh context の `agent_type: toki` と `fork_turns: none` でのみ
起動する。Toki は、上記の共通契約、必須正本、およびこのファイルだけを読み、指定した
`toki.md` だけを作成する。時間上限は15分、外部再試行は0回とする。

## 共通の停止条件

以下が必要になったら、推測で進めず成果物に観測事実・影響・最小質問を残して停止する。

- 人間の判断なしに安全境界、正本方針、または `tmp/` 例外の範囲を確定する必要がある。
- 指定出力以外への書き込み、実装、VCS、ネットワーク、または外部コマンド実行が必要になる。
- 役割の既存責務を越えて、別担当の結論を代行する必要がある。
