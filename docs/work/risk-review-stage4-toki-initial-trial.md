# Toki Stage 4 初回試運転 Rinリスクレビュー

- レビュー者: Rin（凛）
- レビュー日: 2026-07-19
- 状態: **初回レビュー完了・P1対応待ち**
- 対象: `TC-1`、`EP-1`、G3/G4承認記録、固定入力、
  `test-analysis.md`、Gen評価
- 推奨: **現状の「1サンプルの契約適合証跡」は保留**

成果物内容には、固定母集団の追跡、QA技法から項目への導出、不足時の
`inconclusive`維持という有用な増分がある。一方、手続承認の証拠、契約適合と呼べる
証拠範囲、オラクルが参照する入力版にP1が残る。P1対応前に条件付き採用すると、
未検証の実行境界まで適合済みと再利用されるおそれがある。P0は確認していない。

## 1. 重大度順の指摘

以下は、対象箇所、失敗パターン、緩和策、人間判断、差分再レビュー対象を一組で示す。

### P1-1: G5承認を確認できる証拠がレビュー入力にない

- **対象箇所:** `TC-1` 10節のG5、G3承認記録4節、G4承認記録5節、
  Gen評価1節「承認済みFast Laneの範囲」。
- **根拠:** G3記録とG4記録は、どちらもG5のdispatchを未承認範囲として明記する。
  Gen評価はG5承認済みと述べるが、承認者、承認時刻、承認したdispatch引数、停止条件、
  原子的dispatchの残留リスクを照合できる記録は今回のread allowlistにない。
  証拠がないことを、承認がなかったとの断定には使わない。
- **失敗パターン:** 後段の自己申告と成果物品質が良好なため、非省略ゲートの証拠欠落を
  見落とし、未承認dispatchだった可能性を閉じないまま試運転を採用する。
- **代替案または緩和策:** G5の人間承認記録を差分再レビュー入力へ追加し、少なくとも
  承認者、時刻、`agent_type: toki`、`fork_turns: none`、停止条件、原子的dispatchの
  残留リスク受容をG5より前の承認から独立して照合可能にする。記録を提示できない場合は、
  本試運転を「手続適合未確認」として保留する。
- **人間が判断すべき事項:** G5証拠を提示して継続するか、手続証拠不足として今回の
  試運転を保留するか。
- **差分再レビュー対象:** G5承認記録と、それを根拠にしたGen評価1節の記述だけ。

### P1-2: 「契約適合証跡」が観測できた範囲より広い

- **対象箇所:** Gen評価1節、5節`GE-03`〜`GE-05`、6節
  「1サンプルの契約適合証跡として条件付き採用候補」。
- **根拠:** 観測できたのはdispatch要求、platform応答、成果物、Toki自己申告、
  完了後15分以内の更新ファイルである。Gen自身が、read非逸脱、全write非逸脱、
  fresh context、独立操作監査、再現性を未証明と明記する。時刻近傍の更新観測では、
  read、リポジトリ外write、外部送信、一時的変更後の復元、実行主体の完全な帰属を
  除外できない。`TC-1`は成果物構造だけでなく、これらの実行境界も契約に含む。
- **失敗パターン:** 「契約適合」という短いラベルだけが後続へ引用され、自己申告に
  とどまるallowlist、write非逸脱、fresh性まで検証済みと誤認される。そこからToki加入、
  Stage 4完了、または技術方式の安全性へ誤接続される。
- **代替案または緩和策:** 推奨の対象を「`test-analysis.md`の内容契約に対する
  1サンプルの適合候補」へ狭める。評価表を、`観測済み / 自己申告のみ / 未検証`の
  3区分に分け、実行境界を採用根拠から除外する。「契約適合」を維持するなら、
  未検証軸を契約適合の対象外とする定義を先に人間判断へ戻す。
- **人間が判断すべき事項:** 成果物内容だけを条件付き採用するか、実行境界を含む
  契約適合の証拠が得られるまで保留するか。今回の結果だけでToki加入、Stage 4完了、
  案A/B/C採用、安全性判断へ進まないことも明示承認する。
- **差分再レビュー対象:** Gen評価6節の推奨文、観測区分表、および後続判断の除外範囲。

### P1-3: 各テスト項目のオラクルが一意な入力版へ固定されていない

- **対象箇所:** `TC-1` 6節「オラクルの根拠と入力版」、`test-analysis.md`冒頭、
  6節`TI-01`〜`TI-11`、9節「入力のSHA-256、内容版は未検証」、Gen評価3節`GE-01`。
- **根拠:** 各項目は入力パス、案の記述、将来承認される仕様を根拠として示すが、
  `architecture-options.md`の一意な内容版またはG4 digestへ結合されていない。
  「技術方式未採用版」は状態名であり、内容を一意に再現する版ではない。TokiがG4記録を
  読まずdigestを発明しなかった判断は妥当だが、契約必須属性が充足したことにはならない。
- **失敗パターン:** 入力が更新された後、古い分析項目が新しい入力へのオラクルとして
  再利用され、どの原文から期待値を導いたか復元できない。Gen側のG4記録との暗黙結合も、
  項目単体の転記時に失われる。
- **代替案または緩和策:** 初回成果物を後から書き換えて証跡を変えず、Gen評価へ
  「全TI項目はG4 digest
  `b2be3698f34b92d4056d4460413c0cafdc37fdcd824ceb623748322922bd82cf`
  の入力を分析した」と明示的に結合する。同時に、原成果物では入力版属性が不足した
  契約差分として記録する。将来契約では、Tokiが読める契約本文へ承認済み入力識別子を
  入れるか、項目群が継承する一意な入力版欄を必須にする。
- **人間が判断すべき事項:** この属性不足を記録したうえで内容適合候補を許容するか、
  必須契約違反として今回を保留するか。
- **差分再レビュー対象:** Gen評価の入力版結合、契約差分の明示、および次回契約の
  入力版ルール。原`test-analysis.md`の遡及修正は再レビュー対象にしない。

### P2-1: draft境界が項目単体の転記に耐えない

- **対象箇所:** `TC-1` 6節の各項目必須属性、`test-analysis.md` 6節冒頭と
  `TI-01`〜`TI-11`、Gen評価3節`GE-02`。
- **根拠:** `状態=analysis-draft / 承認者=なし / ゲート利用不可`は6節冒頭で
  一括適用されるが、各項目本文には反復されない。文書内では意味が通る一方、項目だけを
  Issue、テスト管理票、別成果物へ転記すると境界が消える。
- **失敗パターン:** `pass/fail`条件だけが切り出され、人間承認済みゲートまたは
  実結果と誤認される。
- **代替案または緩和策:** 初回成果物は証跡として保持し、後続で項目を転記する場合は
  状態3属性を各行へ付ける。次回契約では、一括継承を認めるか、各項目への明記を要求するか
  を曖昧にしない。
- **人間が判断すべき事項:** 初回成果物内の一括適用を許容するか。許容しても、
  項目単体をゲートへ転用しない。
- **差分再レビュー対象:** Genの扱い方と、次回契約の状態属性ルール。

## 2. EP-1標本評価への反対意見

標本9要素の状態分類について、入力原文と矛盾する重大な誤判定は確認していない。
ただし、標本評価の成立範囲を超えた能力評価には使えない。

- `REQ-009`、`REQ-010`、`OQ-001`を上流質問とした判断は、本文不足を補完しておらず妥当。
- `DES-A-NON`、`DES-B-NON`、`XRISK-02`は代替経路へ具体化され、入力の非成立条件と整合する。
- `DES-C-LIM`、`XRISK-04`は記録欠落、非観測、誤帰属へ展開され、記録不存在を
  非逸脱証明にしていない。
- `UNKN-03`を実行不能とした判断は、網羅監査・主体帰属が未確認で、実テスト禁止という
  入力に整合する。
- **P2の残留リスク:** `EP-1`はGenが契約・母集団・評価計画を作成して評価する
  単一評価者の標本であり、完全なblind評価、独立監査、Toki固有価値、再現性を示さない。
  Gen評価もこの限界を記録しているため、今回の標本を一般能力やStage 4完了へ外挿しない。

## 3. 契約適合の確認結果

以下は、指摘以外の確認結果である。「確認」は文書内容の照合であり、実テストまたは
独立操作監査を意味しない。

- 必須9セクションは存在する。
- 固定母集団は51要素を1要素1行で追跡し、集計
  `被覆16 / 対象外0 / 実行不能4 / 上流質問31`は51と一致する。
- `TOKI-ADD-01`〜`03`は固定母集団の分母外に分離されている。
- QA技法は採否理由だけでなく、条件、デシジョンテーブル、`TI-01`〜`TI-11`の
  導出へ使われている。
- REQ/OQ本文、未確認のCodex機能、技術方式、安全性を確認済みとして発明した箇所は
  確認していない。
- 期待結果は仮説または将来承認仕様と区別され、根拠不足時を`inconclusive`または
  上流質問としている。
- テスト実行、証跡生成、実結果評価、最終合否、Rin重大度、リスク受容をTokiが
  代行した箇所は確認していない。
- 379行の59行超過は、実行行数、理由、圧縮しなかった必須要素を記録しており、
  A2行数ポリシーに適合する。
- Gen評価はToki加入、Stage 4完了、案A/B/C採用、設定変更、実装、PoC、実テスト、
  ADR昇格を明示的に除外している。この除外は維持する。

## 4. 人間へ戻す判断

現時点では、次の順で判断する必要がある。

1. P1-1のG5承認証拠を提示できるか。提示できなければ手続適合未確認として保留する。
2. 採用対象を成果物内容だけへ狭め、read/write非逸脱、fresh性、再現性を未検証として
   除外するか。
3. P1-3の入力版属性不足を契約差分として許容するか、必須契約違反として保留するか。
4. P1対応後、初回成果物を「加入済み」「Stage 4完了」「技術方式採用」へ接続せず、
   1入力・1試行の内容評価として条件付き採用するか。

Rinの推奨は、P1対応前は**保留**、対応後は**成果物内容だけの条件付き採用候補**である。
差分再レビューではP1-1〜P1-3と、P2-1の扱いに変更がある箇所だけを確認し、今回確認済みの
標本評価と契約要素は再掲しない。
