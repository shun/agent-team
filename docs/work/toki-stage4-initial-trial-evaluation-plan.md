# Toki Stage 4 初回試運転 非公開評価計画案

- 作成: 2026-07-19 / 作成者: Gen（玄）
- 状態: **G3確定（2026-07-19人間承認・Toki read allowlist外）**
- 内容版: `EP-1`
- 対象契約: `docs/work/toki-stage4-initial-trial-contract-draft.md`

本書は、Tokiが評価対象へ過適合する可能性を下げるため、Genの標本評価をdispatch前に
固定する。Tokiのread allowlistとdispatch promptへ含めず、試運転後に固定時点と選定規則を
開示する。

## 1. 選定者と固定時点

選定者はGenである。固定日は2026-07-19で、Toki起動と`test-analysis.md`作成より前で
ある。人間が試運転契約を確定するとき、本計画の採用、変更、または却下を判断する。
承認時は、本書の内容版、SHA-256、承認者、承認時刻をTokiのread allowlist外の承認記録へ
残す。承認後に内容が変わった場合は承認を失効させ、dispatch前ならG3からやり直し、
dispatch後なら変更版を当該試運転の評価へ使用しない。

## 2. 非公開標本

標本は、各設計案、高リスクな境界、記録の不存在、未確認事項を横断するよう固定する。

- `REQ-009`と`REQ-010`
- `DES-A-NON`、`DES-B-NON`、`DES-C-LIM`
- `XRISK-02`と`XRISK-04`
- `UNKN-03`と`OQ-001`

## 3. 評価規則

Genは各標本について、次を入力原文とToki成果物で照合する。

- 固定母集団の4状態と根拠が、入力の状態表示・限界と矛盾しない。
- QA技法が名前だけでなく、分割、状態、条件、組合せ、異常、回避経路の導出へ使われる。
- テスト条件と項目が品質リスクへ追跡できる。
- 期待結果、許容集合、オラクル、3値判定が、入力の根拠範囲内で判定可能である。
- 入力に本文がないIDや未確認機能を発明せず、上流質問または実行不能へ分ける。

標本の充足だけで成功扱いにしない。固定母集団全体の追跡、追加リスクの分離、責務境界、
未検証表示も契約適合として確認する。

## 4. 独立性の限界

標本はTokiから非公開だが、母集団と評価観点は試運転契約で公開する。完全なblind評価
ではなく、Genも入力と契約の作成者である。本計画は独立監査、Toki固有価値、再現性、
read/write非逸脱、fresh性の証明にならない。

dispatch前に、人間の確認結果を次の形式で本節へ追記する。現時点では未確認であり、
空欄を承認済みと扱わない。

- 確認者: 未確認
- 確認日: 未確認
- 対象パス: `docs/work/architecture-options.md`
- 対象SHA-256: 未確認
- 秘密情報・認証情報: 未確認
- 個人・顧客・本番データ: 未確認
- 外部送信の有無: 未確認
- 適用範囲: 本試運転1回だけ
