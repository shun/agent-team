## 保留中ルール: コードを書くテーマの進め方(TDD・テスト分析)

(2026-07-05 人間の提案。文言はほぼ原文のまま保存)

1. **Kent Beck 式 TDD**: コードを作成するときは、必ず RED → GREEN → REFACTOR で実施する。ただし、いきなりコードを書くのではなく、必ずテスト分析を行い、どんなテストをすべきかを検討し、**根拠を添えて人間に提案し、テスト分析・テスト項目に関して承認をもらってから**コードを書く
2. **テスト項目の骨組みレビュー**: テスト項目は、テストコードのファイルにコメントやテストの外枠だけ(例: vitest なら describe / it でどんなテストスイート・どんなテストをやるか)を先に作成し、人間にレビューしてもらう。必ず**「なぜこの項目が必要なのか」がわかるように**すること
3. **テスト分析手法の使用**: テスト分析には必ずテスト分析手法を使用する。境界値分析、デシジョンテーブルなど

### 手法の候補(3 への Gen の追加提案。採用可否は反映時に人間が判断)

- 同値分割(境界値分析とセットで)
- 状態遷移テスト(画面遷移・ステータス管理があるとき)
- ペアワイズ / 組み合わせテスト(パラメータの組み合わせが多いとき)
- エラー推測・過去の failure パターン(Rin 加入後はリスク観点と接続)
- リスクベースドテスト(全部は書けないとき、何から書くかの優先順位づけ)
