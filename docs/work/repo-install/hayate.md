## 結論

Hayate が受けられる作業は、要件、設計、テスト条件、
人間判断が固定され、境界と期待結果を事前に固定できる
短い実装に限る。今回は、その前提が揃っていない。
スライス案を推測で埋めない。

固定できない主因は次である。

1. 採用済みの REQ-03 により、人間が PLAN を承認するまで
   実装スライスを開始できない。

   対象リポジトリ、衝突、成功の観測条件が未確定である。
3. Q-I-01 / Q-I-02 / Q-I-03 を採用しないため、配布ルールの
   転用、書込み主体、依頼継続の前提をスライス契約に置けない。

## 後続で固定する場合に必要な契約項目

境界が後から固定される場合に、作業契約へ置く項目である。
値は埋めない。Hayate は欠けた契約を開始しない。

- 作業ID（本作業とは別）。再作業上限。時間上限
- 人間が承認した単一目的。採用した要件ID。不採用の要件ID
- 採用した設計の識別。成立条件と、スライスが触らない限界
- 事前固定した期待結果と検証条件。オラクルの根拠と版
- 入力 allowlist。出力先。直接・間接 write 集合
- 基準版 hash。既存ファイルを更新する場合の技術的 write 隔離、
  対象所有者、write 前競合停止、独立差分確認、復旧主体
- 許可する裁量。停止条件。差戻し条件
- Q-I-01 / Q-I-02 / Q-I-03 を含む、スライスが依存する
  人間判断の採用結果。未採用のまま値を置かない

既存 repository file を更新し、かつ技術的 write 隔離を
用意できない環境では、Hayate へ委譲しない。
