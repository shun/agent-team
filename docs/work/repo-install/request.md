# リポジトリ直インストール実装の計画レビュー

> 状態: 計画中（2026-08-16 人間依頼「リポジトリから直接インストールするための実装を計画して」）
> 進行: Aira
> 対象ディレクトリ: `docs/work/repo-install/`

この成果物は、他リポジトリへ agent-team を配布・導入する実装を計画するための
共通契約である。各担当は、このファイルと必須正本、および後続で指定された
入力だけを読み、指定された自分の成果物だけを作成する。

## 目的

人間が「いろいろなリポジトリに対してインストール出来るようにしたい。
リポジトリから直接インストールするための実装を計画して」と依頼した。
実装や調査の開始前に、7役が Markdown 成果物で判断材料を揃え、人間が
採用 / 却下 / 保留できる提案にする。

## 人間が指定した挙動

- いろいろなリポジトリに対してインストールできるようにする。
- リポジトリから直接インストールするための実装を計画する。
- 今回は計画である。実装・VCS・deploy は、人間が PLAN を承認するまで行わない。

## Aira が観測した事実（仮説ではない）

2026-08-16 時点のこの checkout で確認した。

- ルートに README も install スクリプトも package.json もない。
- 配布候補になり得る正本・アダプタは少なくとも次である。
  - `AGENTS.md`
  - `docs/agent/team.md`
  - `docs/agent/safety.md`
  - `docs/agent/workflow.md`
  - `docs/roadmap.md`
  - `.codex/agents/*.toml`（6役）
  - `.claude/agents/rin.md`
  - `.agents/agents.md`
  - `.agents/workflows/agent-team.md`
  - `.agents/skills/agent-team/SKILL.md`
  - `.agents/skills/team-plan/SKILL.md`
- `scripts/run-plan.ts` は、このリポジトリ内の `tmp/PLAN.md` 実行入口である。
- `mission-room/` はデモアプリであり、チーム定義の正本ではない。
- `docs/roadmap.md` は「一括セットアップはしない。最初の一人を最小構成で生み、
  少しずつ育てる」と明記している。
- 現行 safety は、エージェントによるリポジトリ外への書き込みと、人間承認なしの
  正本変更を禁止する。インストーラが対象リポジトリへファイルを書く行為は、
  このリポジトリのエージェント作業とは別の、導入先での人間操作として扱う必要がある。

## 固定する前提と安全境界

- 人間が最終判断者である。未確認事項・リスク受容・設計採否をエージェントだけで
  決めない。
- 受け渡しは役割ごとの Markdown 成果物で行う。
- Mission Room 実装、既存の未コミット差分の片付け、VCS、deploy は対象外。
- 完了済みの `tmp/PLAN.md`（`team-plan-runner-2026-08-16`）は、7役の成果物が揃い、
  material な不明点が解消し、人間が新しい PLAN の開始を承認するまで上書きしない。
- 担当は指定成果物以外を変更せず、実装・VCS・ネットワーク・外部送信を行わない。
- 秘密情報・生ログを成果物に書かない。

## レビュー論点

1. 「インストール」の対象物、非対象、成功状態。
2. 「リポジトリから直接」の意味（git URL、raw URL、GitHub テンプレート、
   パッケージレジストリなし、など）。
3. 導入先リポジトリの既存ファイルとの衝突、上書き、更新、アンインストール。
4. このリポジトリ固有の実験場ルールを、他リポジトリへコピーしてよいか。
5. インストーラ実装の置き場、実行主体（人間が対象 repo で叩く）、安全境界。
6. 実装タスクへ落とすときの依存、完了条件、検証可能性。

## 共通の停止条件

以下が必要になったら、推測で進めず成果物に観測事実・影響・最小質問を残して停止する。

- 人間の判断なしに安全境界、正本方針、配布物の範囲を確定する必要がある。
- 指定出力以外への書き込み、実装、VCS、ネットワーク、外部コマンド実行が必要になる。
- 役割の既存責務を越えて、別担当の結論を代行する必要がある。
