# agent-team 育成ロードマップ(成長型ブートストラップ)

このリポジトリに AI エージェントチームを導入するためのロードマップ。

一括セットアップはしない。**最初の一人(Gen)を最小構成で生み、Gen と人間が対話しながらチームと土台を少しずつ育てる。** 新メンバーは必要になったときに一人ずつ迎える。すべての変更は「小さく試す → 振り返る → 人間が承認する → 定義に反映する」の成長ループを通す。

設計思想の元ネタは [original-memo.md](notes/original-memo.md)(凍結コピー)。

**このファイルは計画の正本であり、進捗管理はしない。** 進行中 Stage の進捗の正は `docs/work/current-task.md`。各 Stage の「状態」行だけを、Stage の節目に人間の承認をもって更新する(2026-07-05 人間判断: 進捗の二重管理をやめ一本化)。

## 成長ループ(すべての変更の基本サイクル)

エージェント定義・docs・ワークフローの変更は、大小問わずこのループを通す。

```
1. 気づき・提案(人間 or エージェント)
2. 小さく試す(実タスクで使ってみる)
3. 振り返り(何が良かったか / 何がダメだったか)
4. 人間が判断(採用 / 却下 / 保留)
5. 採用分だけ正本 docs に反映し、growth-log に記録
```

memo セクション23 は「自己成長機構」を MVP 外としているが、あれは自動化された成長基盤のこと。ここでの自己成長は**人間承認つきの定義改善ループ**であり、自動化はしない。この解釈の違いは意図的なもの。

## 育成の原則

- **一度に迎えるのは一人まで。** 前のメンバーの試運転と振り返りが終わるまで次を迎えない
- **ファイルは必要になってから作る。** 最初から14ファイル置かない
- **人間の承認なしに正本(docs / エージェント定義)を変えない**
- **進捗の正は current-task.md。** roadmap は計画と各 Stage の状態行のみを持つ
- **名前だけ増えて出力が変わらないメンバーは削る**(失敗条件)
- 迎える順序・役割分担は固定ではない。成長ループの中で人間と Gen が見直してよい
